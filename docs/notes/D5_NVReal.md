## 0. 一段话总结

项目的主模型是在 **Nutrition5K**（固定深度相机俯拍餐厅菜品）上训练的食物重量/营养素估计系统。NV-Real 实验回答了一个审稿人必问的问题：**"换到普通人用手机随手拍的照片，你的系统还剩几成功力？"** 答案是：点估计（重量数值预测）严重退化（误差从 31.4% 涨到 103.7%），不确定性区间（"我有 90% 把握真值在这个范围里"的承诺）也崩溃了（承诺 90%、实际只罩住 33%）；但**把两个数据集混在一起联合训练后，新问题几乎全部解决且老问题零代价**——证明瓶颈在数据多样性，不在模型架构。

## 1. 背景：这个项目在做什么

在讲实验之前，先理解项目的三根支柱：

1. **食物重量估计**：给一张菜品照片，模型预测这盘菜多重（克）。主模型输入是 4 通道图像 = RGB 彩色 3 通道 + 深度（Depth，每个像素离相机的距离）1 通道，简称 **4ch / RGB-D 模型**。
2. **营养素估计**：预测这盘菜的热量（kcal）、脂肪、碳水、蛋白质。做法是「重量 × 营养密度」。
3. **共形预测（Conformal Prediction）**：这是本项目的核心方法论。它不仅给一个预测数字，还给一个**区间**，并做出数学保证——"真实值有 90% 的概率落在这个区间内"。打个比方：普通模型说"这盘菜 300 克"；带共形预测的模型说"这盘菜 300 克，而且我有 90% 把握真值在 220–380 克之间"。

**为什么需要第 3 点？** 因为食物重量估计误差天然很大（论文论证了纯视觉存在约 18.4% 的误差天花板），一个诚实的"我不确定"比假装精确更有价值——比如给糖尿病人估算碳水时，系统可以说"这餐碳水在 40–60g 之间，把握 90%"，用户可以据此决定是否追加测量。

## 2. NV-Real 是什么数据集？和训练数据差在哪？

| 对比项 | Nutrition5K（训练集，简称 N5K） | NutritionVerse-Real（测试集，简称 NV-Real） |
|---|---|---|
| 采集方式 | Intel RealSense **固定**深度相机，实验室俯拍 | 真实生活中 **iPhone 随手拍**，任意角度/距离/光照 |
| 有无深度图 | 有（模型的重要输入） | **没有**（纯 2D 照片） |
| 规模 | 数千菜品 | 889 张照片 / 251 个菜 / 45 种食物类型 |
| 重量标注 | 逐食材称重 | 逐食材称重（每菜约 3.5 张不同角度照片） |
| 出处 | Google | arXiv 2401.08598，Kaggle 免费下载 |

**关键认知**：这两个数据集的差异（术语叫**域偏移 / domain shift**）是"教科书级别的大"——相机不同、有无深度不同、拍摄习惯不同、菜品风格不同。这正是实验的价值所在：如果系统连这种差异都能扛住，说明它真的能部署到现实世界。

## 3. 专有名词小词典（读结果前必看）

| 名词 | 通俗解释 |
|---|---|
| **MAE**（平均绝对误差） | 预测重量和真实重量差多少克，取平均。例：MAE=238.8g 就是"平均每盘菜猜错 238.8 克"。**越小越好**。 |
| **PMAE**（百分比平均绝对误差） | MAE 的百分比版：误差 ÷ 真实重量，再平均。一盘 100g 的菜猜成 150g，误差就是 50%。**越小越好**；超过 100% 意味着"平均错了一倍多"，基本不可用了。 |
| **pp（百分点）** | 两个百分比数字的差。31.4% → 103.7% 叫"退化 +72.3pp"，不叫"涨了三倍"（虽然也确实是三倍多）。用 pp 是为了避免歧义。 |
| **R²（决定系数）** | 衡量"模型比直接猜平均值强多少"。R²=1 完美；R²=0 等于只会猜平均值；**R² 为负 = 比直接猜平均值还差**。 |
| **Spearman ρ（秩相关）** | 衡量"排序对不对"：把 10 盘菜按重量排队，模型排的队和真实的队有多一致。ρ=1 完全正确，ρ=0 等于瞎排。0.16 意味着排序能力接近随机。 |
| **收缩比（0.55×）** | 预测值的分散程度 ÷ 真实值的分散程度。真实菜从 50g 到 800g 分布很广，但模型预测都挤在中间——收缩比 0.55 说明模型"不敢猜极端值"，向它训练时见过的典型份量回归。这是模型失效的典型指纹。 |
| **零样本（zero-shot）** | 模型**从未见过**目标数据集的任何样本，不训练、不微调、不调参，直接拿去测。是最严格、最诚实的泛化测试。 |
| **共形预测 / 共形区间** | 见第 1 节。核心产出一个"90% 区间"：承诺真值 90% 概率落在区间内。 |
| **覆盖率（coverage）** | 事后检验承诺是否兑现：1000 个菜的 90% 区间，应该约 900 个罩住真值。实际罩住的比例就是覆盖率。**理想 = 90%**；低于 90% 叫"覆盖不足"（承诺是空头支票），远高于 90% 说明区间给得太宽太保守。 |
| **区间宽度** | 区间的长度（克）。同样 90% 覆盖率，区间越窄越有用。"0–1000g 之间"虽然必中但毫无价值。 |
| **校准器（calibrator）** | 共形预测里决定"区间要多宽"的部件，用一小批**校准数据**（不参与训练）拟合出来。本项目在 N5K 上拟合好后**冻结**（不再改动），直接拿去 NV-Real 上用——这正是要检验的脆弱点。 |
| **可交换性（exchangeability）** | 共形预测 90% 保证成立的数学前提：校准数据和测试数据来自**同一个分布**（通俗说"是同一类照片"）。NV-Real 和 N5K 显然不是，所以这个实验是"故意违反前提，看保证崩多少"。 |
| **Split / Normalized / MondrianW** | 共形预测的三种具体做法：Split 是最基础版（所有样本共用一个区间宽度）；Normalized 按预测难度缩放宽度；MondrianW 按重量大小分箱、每箱单独定宽度。本实验显示：**三种都崩，分箱也救不了**。 |
| **模态差 vs 域差** | 本实验把总退化拆成两笔账：**模态差** = 失去深度通道的代价（4ch→3ch，+9.4pp）；**域差** = 换数据集的纯代价（+72.3pp）。结论：大头是域差，不是缺深度。 |
| **刚体（rigid）vs 制备（prepared）食物** | 刚体 = 形状固定的食物（一颗蓝莓、一块饼干），体积好估；制备 = 形状不定的食物（沙拉、炒饭、汤），同样重量体积可大可小。项目的一个重要叙事是"制备食物天生更难"。 |

## 4. 实验总览：在 NV-Real 上一共做了 5 件事

| # | 实验 | 对应研究问题 | 一句话结果 |
|---|---|---|---|
| 1 | **零样本跨域点估计**（重量预测） | RQ1：换个世界，重量误差退多少？ | 退化剧烈：PMAE 31.4% → **103.7%** |
| 2 | **冻结共形覆盖检验** | RQ2：90% 区间承诺还作数吗？ | 崩溃：覆盖率 86% → **33%** |
| 3 | **刚体/制备类别结构迁移** | RQ3：退化规律是否符合"制备更难"的叙事？ | 符合：刚体 318% < 制备 606% |
| 4 | **多域联合训练**（实验 22） | 补救：域差能被数据买回吗？ | 能：77.4% → **23.9%**，且源域零代价 |
| 5 | **少样本恢复**（`backup/caia_mm/experiments/e08_cross_domain.py`，不进入当前方案） | 目标域给少量校准样本，承诺能恢复吗？ | 零样本覆盖 61.4%（子集口径），恢复随校准数递增 |

> 实验 1–4 是论文主实验（paper §5.8，实验记录 21/22）；实验 5 是后续 Agent 扩展层（CAIA-MM）里的跨域环节，协议口径不同（57 个测试 episode），作为补充视角。

所有实验遵守一条**诚实铁律**：NV-Real 上零训练、零校准、零调参（实验 4/5 的"用 NV-Real 数据"部分有独立的防泄漏划分），坏结果照登。

### 4.1 一个关键技术决策：模型要吃深度图，NV-Real 没有，怎么办？

主模型是 4 通道（RGB+深度），NV-Real 是纯 2D 照片。方案对比：

- **方案 A（深度置零）**：把深度通道填 0 直接喂。测的是"喂错模态"的最坏情形。
- **方案 B（论文主用）**：在 N5K 上重新训练一个 **3 通道（纯 RGB）版模型**，超参数和随机种子完全不变。域内（N5K hold-out）成绩 31.4%（4ch 是 22.0%）。

于是账算清了：**模态差 = 31.4 − 22.0 = +9.4pp**（深度通道值 9.4 个百分点），剩下 NV-Real 上多出来的误差才是纯**域差**。

### 4.2 过程中抓到的两个数据 bug（诚实性记录，也是项目惯例）

1. **NV-Real 标注的"重复列覆盖"bug**：同一盘菜里有 3 份鸡胸肉时，标注文件写成 3 个同名列，初版代码只保留最后一列（覆盖了前两份），导致 29%（766/2614）样本的真值被低估。修复 = 同类别**求和**，并用全部 251 个菜的"各列之和 == 总重"校验和验证自洽。
2. **任务错位 bug**：初版拿"整盘菜模型"去测"单食材裁剪"，得到 694% 的无效数字，整版作废重写（对齐协议：所有食物 mask 取并集 → 外扩 20px → 抠掉背景 → 标签用整盘总重），最终得到 880 个菜品级有效评测。

这两个 bug 的修复记录完整保留在仓库里（`results_audit/`），体现项目"失败也留痕"的惯例。

## 5. 实验 1（RQ1）：零样本跨域点估计 —— "换个世界，还猜得准吗？"

**做法**：N5K 上训练的 3ch 模型，原封不动（冻结）去预测 NV-Real 880 盘菜的重量。

**结果**：

| 指标 | 域内（N5K） | NV-Real 零样本 | 怎么读 |
|---|---|---|---|
| PMAE | 31.4%（3ch）/ 22.0%（4ch） | **103.7%** | 误差翻了三倍多；103.7% 意味着"平均每盘菜猜错一整个菜的重量还多" |
| MAE | — | **238.8 g** | 一盘典型午餐 400–600g，平均猜错约 240g，约等于半盘菜 |
| R² | — | **−0.16** | 比"闭眼全猜平均值"**还差** |
| Spearman ρ | 0.75 | **0.16** | 排序能力从"基本靠谱"掉到"接近抽签" |
| 预测/GT 中位比 | — | 5.5×（小菜）→ 0.42×（大菜） | 小菜严重高估、大菜严重低估——所有预测都往"训练集典型份量"挤 |

**怎么理解这个崩溃？** 这叫"**向训练先验坍缩**"。域内时，模型其实在大量"作弊"：它记住了 N5K 的餐盘大小、餐厅标准份量、固定俯拍角度下"占画面多少 ≈ 多重"的对应关系。这些线索（术语叫**外观先验**）在 NV-Real 里全部失效——手机照片没有固定相机几何、没有统一餐盘。线索蒸发后，模型只剩一招：猜训练集里最典型的重量，于是小菜猜太多、大菜猜太少、排序基本随机。

**一个对照**：盲目地把 N5K 的中位数重量当作所有预测的 MAE 是 245.1g，模型是 238.8g——模型在 MAE 上只比瞎猜好一点点，在 PMAE 上反而更差（因为它系统性高估小份菜）。

> 口径注意：论文另有一处报 **77.4%**，那是实验 4 里"按菜品划分的 177 菜 hold-out 子集"上的零样本成绩；103.7% 是全部 880 图的成绩。两个数字协议不同，不矛盾。

## 6. 实验 2（RQ2）：冻结共形覆盖检验 —— "90% 的承诺还兑现吗？"

**做法**：把在 N5K 校准集上拟合好的三种共形校准器（Split / Normalized / MondrianW）**原样冻结**，直接套在 NV-Real 的预测上，统计真值落在区间里的比例。

**结果（核心表）**：

| 90% 区间类型 | 域内覆盖率 | NV-Real 覆盖率 | 区间宽度 |
|---|---|---|---|
| Split | 85.9% | **32.8%** | 217g（冻结不变） |
| Normalized | 88.2% | **53.6%** | 414g |
| MondrianW（分箱） | 85.4% | **41.5%** | 297g |

**怎么读**：
- 你向用户承诺"90% 把握"，实际只有 33–54% 的真值被罩住——**承诺变成了空头支票**。这不是区间不够宽的问题，而是区间的**位置**错了：预测值本身偏了，以预测值为中心的区间自然罩不住真值。
- **分箱（Mondrian）也救不了**：它在小菜箱里学的是 N5K 的误差规律，到 NV-Real 误差规律完全不同，逐箱校准等于校准了个寂寞。这证明共形预测"与分布无关"的保证，前提是**可交换性**（校准/测试同分布），它**不是**跨域免死金牌。
- **哪里崩得最狠**（论文图 3 的分箱分解）：0–100g 的小菜覆盖率从 99% 暴跌到 **26%**（模型把小菜高估，区间中心被推到了真值上方）；500g+ 大菜在 Split 下从 47% 跌到 15%。基预测器偏置越大的区间，崩得越惨——误差和偏置是"一伙的"。
- **要恢复 90% 覆盖的代价**：得把区间的关键参数（共形分位数 q）从 108.5g 膨胀到 484.3g，即 **4.46 倍宽**。这相当于把"90% 区间"变成"几乎可以确定的废话区间"。**4.46× 就是域外不确定性的价格标签**。

**营养素侧同样崩溃**（冻结的 AEC-S2m-5W 营养校准器）：

| 指标 | 域内 | NV-Real |
|---|---|---|
| 区间覆盖率 | 91.1% | **44–56%**（四种营养素） |
| PMAE：热量 / 脂肪 / 碳水 / 蛋白质 | 22.8 / 36.5 / 39.4 / 33.7% | **64.8 / 69.5 / 163.2 / 95.3%** |

读法：营养 = 重量 × 密度，重量已经错了 103%，营养素自然被拖垮。碳水 163.2% 最差，部分原因是 NV-Real 有很多近零碳水的菜（分母极小，百分比误差爆炸；已在 GT≥1g 子集上计算以缓解，仍然最差）。

## 7. 实验 3（RQ3）：刚体 vs 制备 —— "退化规律符合预期吗？"

**做法**：把 NV-Real 的 45 种食物手工标注为"刚体"（蓝莓、饼干这类形状固定的）或"制备"（沙拉、炒饭这类形状不定的），分组看食材级 PMAE。

**结果**：刚体 **318%** vs 制备 **606%**。

**怎么读**：虽然两组数字都很大（域外整体就崩），但**制备食物退化得明显更狠**，与项目在 §6.2–6.4 用三个独立数据集论证过的"刚体/制备二分"叙事第 4 次吻合。意义在于：域外退化不是无差别噪声，它遵循可解释的物理结构——形状不定的食物，失去深度和参照物后体积最难估。这为"加参照物/深度提示"的补救方案提供了针对性依据。

## 8. 实验 4（实验 22）：多域联合训练 —— "域差能被数据买回吗？"

这是整个 NV-Real 实验的"建设性收尾"：前面证明了问题有多严重，这里证明问题**可解**。

**做法**：同一个 3ch 架构，三种训练配置，分别在两个测试集上评测。防泄漏设计：NV-Real 按**菜品**划分（180 个菜训练 / 45 个菜测试），保证测试菜的照片绝不在训练里出现过（同一盘菜的多角度照片不会一边一张）。

**结果**：

| 训练数据 | N5K 测试集（652 菜） | NV-Real 测试集（177 图） |
|---|---|---|
| 仅 N5K（=零样本） | 31.4% | 77.4% |
| 仅 NV-Real | 124.7% | 25.6% |
| **联合（N5K + NV-Real）** | **31.5%** | **23.9%** |

**怎么读**（三个看点）：

1. **联合训练几乎完全买回了域差**：NV-Real 上 77.4% → 23.9%，甚至比"只用 NV-Real 训练"（25.6%）还略好——多一份异构数据还有正向帮助。
2. **源域零代价**：N5K 上 31.4% → 31.5%，几乎没变化。老本行没有受损。这是"双赢"而非"拆东墙补西墙"。
3. **反向崩溃是对称的**：只用 NV-Real 训练的模型回到 N5K 上是 124.7%——说明不是 N5K 模型差，而是**任何单一域学出的外观先验都不可双向迁移**。

**结论**：误差天花板是**数据问题，不是架构问题**。想让系统在现实世界可用，答案是多域采集（多种相机、多种场景的数据混合训练），而不是换更大的模型。

## 9. 实验 5（Agent 扩展 E08）：跨域 + 少样本恢复

这是已归档的 CAIA-MM 跨域环节（`backup/caia_mm/`），与论文主实验口径不同（57 个测试 episode 的子集），作为补充：

- **零样本**：覆盖率 0.614（61.4%），且代码里明确标注 `claim_90: False`——**零目标域校准时，不允许声称 90% 保证**，这是写进预注册（preregistration H4）的纪律。
- **少样本恢复**：给目标域 n = 25 / 50 / 100 / 200 个校准样本重新拟合区间宽度，检验覆盖率是否随 n 单调回升——回答"部署时只需要标定多少张照片，就能把承诺赎回来"。
- **OOD 拒判门**：预测值偏离 N5K 中位数太远（用中位数绝对偏差 MAD 归一化，阈值 2.5）时系统**弃权不答**，并统计"灾难性错误（相对误差 >100%）有多少被这个门拦下"。这是给 Agent 的"知道自己不知道"能力。

**怎么读**：主实验（实验 2）告诉你"直接部署，承诺崩溃"；E08 告诉你"崩溃是可修复的，而且修复成本可以量化"——少量目标域校准样本 + 一道拒判门，是从"论文结论"走向"可部署系统"的桥梁。

## 11. 这个实验为什么重要（论文里扮演什么角色）

1. **替换了论文 Limitations 里的一句空话**。原来只写"跨数据集泛化尚待验证"，现在 Limitations #6 是一整段实测数字。
2. **是共形预测方法论的教科书级案例**：用真实数据展示了"可交换性假设被破坏时，分布无关保证具体崩多少、崩在哪"。
3. **给 18.4% 误差天花板定位**：天花板是**域相对**的——域内外观先验部分替代了深度信息，域外先验蒸发。这成为论文建议"拍摄时放参照物 + 域自适应路由"的第 5 个独立论据。
4. **从"认怂"升级为"有解"**：多域联合训练的双赢结果，把 limitation 变成了已量化的工程路线。
