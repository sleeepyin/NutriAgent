## 起始协议

起始协议接 [#78](https://github.com/sleeepyin/NutriAgent/pull/78) 附录。第一阶段可以收紧字句，但必须在任何训练之前写死。盘级总量仍以 Hand 盘级表为准。部分标签只影响食材分解，不影响盘级总量本身。

[#78](https://github.com/sleeepyin/NutriAgent/pull/78) 用来判断求和是否对齐的容差是起点：某个营养素算对齐，当绝对差不超过 0.5，或不超过较大绝对值的 1%，二者取更宽的那个。五个营养素同时落在容差内，该盘才算在求和上对齐。第一阶段把这条容差和下面的定义一起写死。

1. **可见实例**是能在这张俯视 RGB 上描出边界的食材。Hand 的 2922 行就是这个集合，类别是 40 个粗类。
2. **有营养的实例**是 `has_nutrition=1`，且质量、能量、脂肪、碳水、蛋白质都不是空值的行。空值是缺失，不能当成 0 克或 0 千卡。
3. **完整标签盘**是每个可见实例都有营养，并且这些实例在五个营养素上的求和与盘级表都落在容差内。
4. **部分标签盘**上，盘级总量减去已标注实例之和，是未标注残差。残差可以来自没有营养字段的可见实例，也可以来自没有画进掩膜的成分。Hand 等人写明，油和糖这类在 RGB 里分不出来的成分没有画进掩膜。残差不是「该成分质量为零」的负例，也不能在这次审计里当作新的监督。
5. **盘级质量、能量和宏量**仍以 Hand 盘级表为准。
