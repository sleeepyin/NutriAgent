## 已冻结的协议

下面的定义已经在第一阶段写死，冻结在 `scripts/u2_phase1_partial_label_audit.py`。第二阶段不得再收紧或放宽。看到留出营养误差之后不得改定义或容差。盘级总量仍以 Hand 盘级表为准。部分标签只影响食材分解，不影响盘级总量本身。

某个营养素算对齐，当绝对差不超过 0.5，或不超过较大绝对值的 1%，二者取更宽的那个。五个营养素同时落在容差内，该盘才算在求和上对齐。

1. **可见实例**是能在这张俯视 RGB 上描出边界的食材。Hand 的 2922 行就是这个集合，类别是 40 个粗类。
2. **有营养的实例**是 `has_nutrition=1`，且质量、能量、脂肪、碳水、蛋白质都不是空值的行。空值是缺失，不能当成 0 克或 0 千卡。`has_nutrition=0` 不加进可见求和。一个有营养实例都没有时，可见求和不记成 0，残差没有定义。
3. **完整标签盘**是每个可见实例都有营养，并且这些实例在五个营养素上的求和与盘级表都落在容差内。
4. **部分标签盘**上，盘级总量减去已标注实例之和，是未标注残差。残差可以来自没有营养字段的可见实例，也可以来自没有画进掩膜的成分。Hand 等人写明，油和糖这类在 RGB 里分不出来的成分没有画进掩膜。残差不是「该成分质量为零」的负例，第一阶段审计也不把它当成新的监督。
5. **盘级质量、能量和宏量**仍以 Hand 盘级表为准。

这五条是问题、残差刻画和 B3 所用的协议。B2 故意把缺营养当成 0。强迫加和故意把残差摊回可见食材，而且只作诊断。这两条对照不改写上面的定义。B3 把残差当作单独剩余项来预测，不摊回可见类别。
