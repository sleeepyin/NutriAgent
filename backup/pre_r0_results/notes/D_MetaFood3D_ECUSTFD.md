## 0. 一段话总结

项目主模型是在 Nutrition5K（固定深度相机俯拍菜品）上训练的食物重量/营养素估计系统，此前已发现一个"**18.4% 误差天花板**"：在严格测试协议下，单张照片估重量的误差怎么都压不到 18.4% 以下。MetaFood3D 和 ECUSTFD 这两组实验回答的是天花板**为什么存在、以及怎么绕过去**：

- **MetaFood3D（§6.2–6.3，三个实验）**：证明天花板的主要成因不是"几何量不准"，而是"**密度看不见**"——同样一碗蓝莓，堆得松和堆得实，重量差 33%，但照片上看不出来。连 2025 年最强的单图 3D 重建模型（SAM 3D Objects）也跨不过这个坎。
- **ECUSTFD（§6.4，三个子实验）**：给出了建设性答案——在密度"看得见"的刚体食物（苹果、鸡蛋这类形状固定的天然食物）上，**照片里放一枚一元硬币当参照物**，端到端重量误差能压到 12.9%，**低于 18.4% 天花板**。也就是说：天花板可以被突破，但靠的不是更强的模型，而是**往照片里加信息**。

## 1. 背景：先搞懂主线的"18.4% 天花板"

理解这两组实验前，需要知道项目此前已经确立的三件事：

1. **主任务**：给一张菜品照片（RGB 彩色 + 深度图），预测这盘菜多少克，进而算热量/脂肪/碳水/蛋白质。
2. **共形预测（Conformal Prediction）**：本项目核心方法论。模型不只给一个数，还给一个**区间**并做数学保证——"真实值有 90% 概率落在区间内"。好比普通模型说"这盘菜 300 克"，本系统说"300 克，且 90% 把握真值在 220–380 克之间"。这次讲的两个数据集实验本身**不做共形预测**，但它们解释了"为什么误差这么大、区间为什么必须存在"。
3. **天花板**：在 Nutrition5K 上做了 18 项优化全部失败后，重量预测误差停在 **PMAE 18.4%**（≥100g 子集）/ 22.0%（全量），且模型的 R² 只有 0.39——意味着 **61% 的重量差异从图像里根本恢复不出来**。

于是自然产生两个疑问：

- **疑问 A**：这 61% 恢复不了的信息，到底是什么？是"体积量不准"（几何问题）还是别的？→ **MetaFood3D 实验回答**。
- **疑问 B**：如果知道缺什么，能不能用简单办法补上、突破天花板？→ **ECUSTFD 实验回答**。

## 2. 专有名词小词典（读实验前必看）

| 名词 | 通俗解释 |
|---|---|
| **重量 = 体积 × 密度** | 本项目的核心物理公式。1 cm³ 的水重 1g（密度 1.0），1 cm³ 的米饭约 0.8g，1 cm³ 的黄油约 0.9g。想知重量，要么直接回归（主模型做法），要么"量出体积、再猜密度"（本实验拆解的做法）。 |
| **MAPE / PMAE** | 百分比平均误差：误差 ÷ 真实值，取平均，乘 100。100g 的东西猜成 150g 就是 50%。**越小越好**。本文中 MAPE 和 PMAE 是同一个指标的不同叫法。 |
| **pp（百分点）** | 两个百分数的差。25.0% → 27.6% 叫"+2.6pp"，避免"涨了百分之几"的歧义。 |
| **Oracle（先知）实验** | 一种"作弊式"诊断实验：故意把某个环节换成**真值（Ground Truth, GT）**，看还剩多少误差。比如"假设体积测量完美（用真值体积），密度靠猜，重量误差多少？"——这样就能把总误差**分解**到各个环节，定位瓶颈。 |
| **GT（Ground Truth，真值）** | 数据集里用仪器实测的标注：真值重量（秤称的）、真值体积（3D 扫描算的）、真值密度（重量÷体积）。 |
| **LOO（Leave-One-Out，留一法）** | 一种"诚实"的查表协议。要猜物体 A 的密度时，只允许用**同类其他物体**的密度取平均（把 A 自己排除在外），模拟"现实中遇到一个没称过的同类食物"的场景。防止自己查自己的作弊。 |
| **密度查表（density lookup）** | 不训练模型，直接查"这类食物的平均密度"。比如见到苹果就查"苹果平均 0.83 g/cm³"。这是密度估计的最朴素基线。 |
| **类内 / 类间** | 类内 = 同一类别内部（不同苹果之间）；类间 = 不同类别之间（苹果 vs 西瓜）。 |
| **尺度歧义（scale ambiguity）** | 单张照片的根本缺陷：一个小碗近距离拍，和一个大碗远距离拍，像素上可以一模一样大。**没有参照物，照片里的像素不携带真实尺寸信息**。 |
| **零样本（zero-shot）** | 模型从未见过该数据集，不训练不微调，直接测。最严格的泛化检验。 |
| **log-log r（对数相关系数）** | 把估计值和真值都取对数后算相关性（-1 到 +1）。接近 1 = "排序和比例关系对"，哪怕单位不对；接近 0 = 没关系；负数 = 越大越猜小，完全错乱。用对数是因为体积/重量跨越好几个数量级。 |
| **Gate（门槛实验）** | 项目惯例：花钱做大实验前，先做便宜的小实验定"继续/放弃"。Gate 1 过了才做 Gate 2，避免浪费算力。 |
| **刚体 vs 制备食物** | 刚体 = 形状固定的天然食物（一颗蛋、一个苹果），密度稳定；制备 = 加工/混合食物（炒饭、沙拉、一碗蓝莓），同样的东西堆法不同密度就变。 |
| **蓝莓悖论（blueberry paradox）** | 本项目发现的标志性现象：同样是蓝莓，**装碗里**密度波动只有 2.2%，**散堆放**波动高达 33%——差别来自颗粒间的空气缝隙（堆积孔隙率），照片上看不出来，但重量差很多。它是"密度看不见"的具象证据。 |
| **5 折交叉验证（5-fold CV）** | 把数据分 5 份，轮流拿 1 份测试、4 份训练，跑 5 轮取平均。比单次划分更可靠。"物体级"划分 = 按物体分而不是按照片分，防止同一物体的不同照片同时出现在训练和测试里造成泄漏。 |

## 3. MetaFood3D：三个实验（论文 §6.2–6.3）

### 3.0 数据集是什么

MetaFood3D（arXiv 2409.01966）：**625 个真实食物物体**（清洗后；原始 637 个，剔除 2 个负体积、9 个坏体积），覆盖 108 个类别。Purdue 上的完整发行要申请密码，里面有扫描网格、环绕 RGB-D 视频和 Blender 渲染，大约 69 GB。本仓库的实验不用那一份。

用的是 Kaggle 公开包 `darrinbright/metafood3d-dataset`，大约 19 GB，只有 Blender 渲染。解压后放在 `data/metafood3d/data/Processed/Processed/Blender_render_images/`。D1 只读仓库里的标签表。D2 和 D3 只读其中的 `Original/*.png`。另一份大约 3 GB 的真实 RGB-D 视频，当前脚本不读。

每个物体有：

- **真值重量**（秤称，1–2091g）
- **真值体积**（3D 扫描重建，cm³）——这是 Nutrition5K 没有的关键信号
- **真值密度** = 重量 ÷ 体积
- 环绕拍摄的多视角 RGB-D 视频 + Blender 合成渲染图

它让"重量 = 体积 × 密度"这个公式的**两个因子都能单独做实验**——这正是误差分解需要的。

### 3.1 实验一：Phase 1 Oracle 误差预算分解（Gate 1）

**脚本**：`experiments/diagnosis/d1_mf3d_oracle/oracle.py` → 结果 `phase1_results.csv`（625 行）

**要回答的问题**：*"假设体积测量完美无缺，光靠'查密度表'估重量，误差还剩多少？"* —— 如果这个数字很大，说明瓶颈在密度；如果很小，说明只要搞好 3D 重建就行。

**怎么做**（一组 Oracle 对照实验，全部免训练、纯查表）：

| 设置 | 做法 | 含义 |
|---|---|---|
| Oracle-1 | 真值体积 × 真值密度 |  sanity check，必须 ≈ 0%（验证数据没搞错） |
| **Oracle-2** | 真值体积 × **LOO 同类平均密度** | **核心**：体积完美、密度靠查表 |
| Oracle-2b | 真值体积 × LOO 同类中位密度 | Oracle-2 的稳健版 |
| Oracle-3 | 真值体积 × 全局平均密度 | 连类别都不知道时的下界 |
| Oracle-5 | 真值体积 ±ε% 噪声 × LOO 密度 | 灵敏度：体积误差会放大多少到重量上 |

另外直接统计了**密度本身的离散度**：每个物体的密度偏离"同类平均密度"多远（|log(ρ/ρ_LOO)| 的平均，乘 100 变成百分比）。

**结果**（已从 CSV 核验）：

| 指标 | 数值 | 怎么看 |
|---|---|---|
| Oracle-1 | 0.0% | 数据自洽，实验可信 |
| **Oracle-2（全量）** | **25.0% MAPE** | 体积完美 + 密度查表，误差就有 25%——**比整个单目问题（22.0%）还大** |
| **Oracle-2（≥100g）** | **23.4% MAPE** | 同样口径下主模型天花板是 18.4%——查表路线连天花板都打不赢 |
| **类内密度离散** | **21.8%** | "同类食物密度波动"这一个因素，就贡献了和整个单目问题（22.0%）几乎一样大的误差 |
| Oracle-5：体积 ±10% 误差 | 只多 +2.6pp | 体积量错 10%，重量误差才涨 2.6 个百分点——**体积不是瓶颈** |
| 蓝莓悖论 | 装碗 2.2% vs 散装 33% | 密度波动的物理来源是堆积孔隙率，视觉不可见 |

**这组数字怎么读**：
- 直觉上大家认为"重量估不准是因为体积量不准，3D 重建搞好就行"。Oracle-5 否定了这一点：体积误差对总误差影响很小。
- Oracle-2 = 25.0% 才是炸弹性结果：**就算给你完美的体积，密度查表这一条路的上限比现有天花板还差**。瓶颈是**密度，不是几何**。
- 21.8% vs 22.0% 的"巧合"是全文最有力的一个对照：类内密度波动 ≈ 整个单目问题的难度，说明重量误差的账基本可以全记在密度头上。

**Gate 1 判定**：通过（值得继续）——但方向已从"搞 3D 几何"转向"密度能不能从外观学出来"。

### 3.2 实验二：Phase 2' 学习式密度 CNN（Gate 2）

**脚本**：`experiments/diagnosis/d2_mf3d_density/learned_density.py`（GPU 训练，5 折物体级 CV）

**要回答的问题**：*"既然查表不行，能不能训练一个神经网络，看照片直接猜密度？"* —— 如果连深度学习都打不过查表，说明照片里**根本没有**超出"这是哪类食物"之外的密度信息。

**怎么做**：
- ResNet-18（经典 CNN）输入 Blender 渲染的食物照片，输出 log 密度；
- 5 折**物体级**交叉验证（测试物体的照片绝不出现在训练集，但**同类其他物体在**——模拟真实部署："见过苹果，没见过这个苹果"）；
- 三方对比：CNN 预测密度 vs LOO 同类均值查表 vs 全局均值。

**结果**（密度 MAPE，5 折平均）：

| 方法 | 密度误差 | 怎么读 |
|---|---|---|
| 全局均值（最笨基线） | 42.3% | 什么都不知道的水平 |
| **CNN 看照片学密度** | **30.3%** | 比全局好 12.0pp——照片**确实**含有密度信息 |
| **LOO 同类查表** | **26.2%** | 但 CNN **输给查表 4.1pp**——它学到的密度信息没有超出"认出食物类别" |

**怎么读**：这是本实验最精妙的设计。CNN 比全局均值好 12 个点，证明"外观携带密度信息"；但它打不赢最简单的"认出类再查表"，证明**外观携带的恰好就是类别信息，一分不多**。同类食物之间的密度差异（堆得松/紧、怎么做的、含水多少）在照片上没有可学特征。

**Gate 2 判定**：**证伪**。"学密度"路线放弃，"密度不可观测"的范式全面闭合——这就是为什么 §6.2 结论说天花板是**语义性的**（信息不存在），不是几何性的。

### 3.3 实验三：Oracle-6 SAM 3D Objects 零样本体积评测

**脚本**：`experiments/diagnosis/d3_mf3d_sam3d/sam3d_volume.py` → 结果 `oracle6_results.csv`（130 行）

**要回答的问题**：*"前两实验测的是'查表/学习'路线。那 2025 年最强的单图 3D 基础模型，直接从一张照片重建 3D、量出体积，总该行了吧？"*

**SAM 3D Objects 是什么**：Meta 2025 年发布的模型，在 314 万张真实 3D 扫描上训练，输入一张 RGB 照片 + 掩码，输出该物体的 3D 高斯溅射（Gaussian Splatting）重建，并且**自带"尺度先验"**——声称能给出真实尺寸的估计。如果它的尺度先验有效，尺度歧义问题就迎刃而解。

**怎么做**：在 MetaFood3D 上分层抽样 **130 个物体（30 类 × 每类 4 实例 + pilot）**，零样本跑 SAM 3D，把重建出的密度场体素化数格子算体积，和真值体积对比。分两种"空间"看：

- **潜在空间**：模型的原始输出（规范化坐标，无绝对单位）——只作基准；
- **相机空间**：用模型官方管线给出的逐物体尺度因子 s 换算（体积 × s³）——这是模型声称的"真实尺寸"。

**结果**（已从 CSV 核验）：

| 指标 | 数值 | 怎么读 |
|---|---|---|
| 相机空间中位 体积比（估计/真值） | 5.6×10⁻⁵ | 估计体积平均只有真值的**十万分之 56**——绝对尺度完全不可用，metric MAPE = 100.0%（不能再差了） |
| 全局校准后 MAPE | 87.3% | 允许事后乘一个"最佳统一换算系数"救场，误差仍有 87.3%——**不存在一个通用换算能把它的输出变成厘米** |
| 逐类校准后中位误差 | 33.3% | 每类各给一个换算系数才行——它的"尺度先验"不是一把尺，是**三十把各有偏差的尺** |
| **类间 log-log r** | **0.92** | 类别平均体积的排序很对（"杏仁小、西瓜大"）——先验里**有真实的类别级尺寸知识** |
| **类内 log-log r** | 中位 +0.88，范围 **−0.98 ~ +0.99** | 刚体食物（牛油果 +0.98、西兰花 +0.99、三文鱼 +0.99）追得好；**堆叠食物崩溃**：一碗杏仁 −0.10、蓝莓 −0.41、培根 −0.98（越大越猜小，完全反向） |

**怎么读**：
- 三个发现层层递进：① 绝对尺度不可用；② 它的"尺度感"是类别级的（知道西瓜比杏仁大），不是度量级的（不知道这碗杏仁是 200 还是 400 cm³）；③ 连类别内大小排序都只在刚体食物上成立。
- **最有诊断价值的是堆叠食物的失败**：散装蓝莓在 3D 重建端也崩（r = −0.41），和实验一发现的"密度波动 33%"**精确交汇**——堆积孔隙率同时摧毁"重量 = 体积 × 密度"的**两个因子**。这就是蓝莓悖论的 3D 投影。
- 给 SAM 3D 最好的待遇（逐类校准，33.3% 体积误差）× 实验一的密度离散（21.8%）≈ **40% 重量误差**——比要突破的 18.4% 天花板差 2.2 倍。结论：天花板不是本项目模型太弱，**2025 年最强的单图 3D 模型拿着同样的一张照片也逃不出去**。能逃出去的办法（多视角、参照物、语义交互）加的是**信息**，不是模型容量。

## 4. ECUSTFD：硬币参照物实验（论文 §6.4）

### 4.0 数据集是什么

ECUSTFD（arXiv 1705.07632，华东理工，约 390MB）：**19 类刚体/天然食物**（苹果、鸡蛋、猕猴桃等，174 个实例），**2,861 张手机照片**（每实例俯拍 T + 侧拍 S 多组）。三个关键资产：

1. 每张照片里**都放了一枚一元硬币**（直径 25.0mm）——现成的物理参照物；
2. 每个实例有**真值体积**（排水法测的）和**真值重量**；
3. 每张照片有食物和硬币的**标注框（bbox）**。

为什么选它：MetaFood3D 的实验证明了"密度离散"是拦路虎，而 ECUSTFD **全是刚体食物**——正是密度离散小（<15%）的那个子域。如果"尺度歧义 + 密度离散"的双因子分解是对的，那么在这里**硬币消掉尺度歧义后，剩下的路应该能走通**。

### 4.1 E1：尺度歧义量化（硬币到底补上了什么信息）

**要回答的问题**：*"没有参照物时，照片丢失的真实尺寸信息到底有多大？硬币能补回多少？"*

**怎么做**：从标注框算出每张照片的"毫米/像素"（硬币 25mm ÷ 硬币像素直径），看它在整个数据集里波动多大；再对比两种情况下"食物俯拍面积"和"真值体积"的相关性：

- **有硬币定标**：每张照片用自己的毫米/像素换算面积；
- **无定标**（模拟"假设固定距离拍摄"）：所有照片用全局中位数换算。

**结果**：

| 指标 | 数值 | 怎么读 |
|---|---|---|
| 毫米/像素范围 | 0.084 – 8.33 | 跨了**近两个数量级**——人们拿手机拍照的距离/变焦毫无约束。这就是"61% 方差不可恢复"的物理形态：像素本身不带尺寸 |
| 面积-体积 log-log r（无定标） | 0.59 | 固定距离假设下，面积只携带约一半的体积信息 |
| 面积-体积 log-log r（硬币定标） | **0.74** | 一枚硬币就把度量信号明显救回来了 |

### 4.2 E2：真值体积 × LOO 类别密度（体积完美时，这条路的上限）

**怎么做**：和 MetaFood3D 实验一的 Oracle-2 **完全同款协议**——真值体积 × 留一法同类平均密度 → 重量 MAPE。

**结果**：

| 数据集 | 同协议误差 | 怎么读 |
|---|---|---|
| MetaFood3D（多为制备食物） | 25.0% | 密度查表在制备食物上崩 |
| **ECUSTFD（全刚体）** | **7.9%** | 同一个协议在刚体食物上只有 7.9%——**3.2 倍差距几乎全由类内密度离散造成** |

**怎么读**：7.9% 同时低于 MetaFood3D 的 25.0% 和单目天花板 18.4%。它证明"密度不可观测"不是所有食物的宿命，而是**制备/堆叠食物特有的病**；在刚体食物上，"量体积 × 查密度"这条路的理论上界非常好。

### 4.3 E3：端到端全链路（硬币定标面积 × LOO 高度先验 × LOO 密度）

**要回答的问题**：*"E2 用了真值体积（现实中没有）。只用一张照片 + 一枚硬币，完全不上深度学习，端到端能做到多少？"*

**怎么做**（刻意用最粗糙的几何，证明下限）：
1. 硬币定标把食物俯拍面积换算成 mm²；
2. 体积 = 定标面积 ÷ k，其中 k 是"同类其他实例 面积/体积 比值"的中位数（LOO，等价于假设"高度在类内大致恒定"）；
3. 重量 = 估计体积 × LOO 同类密度。

**结果**：

| 指标 | 数值 | 怎么读 |
|---|---|---|
| 体积 MAPE | （脚本输出，逐实例记录在 `ecustfd_reference_results.csv`） | 粗糙几何的中间产物 |
| **端到端重量 MAPE** | **12.9%**（n=174） | **低于 18.4% 天花板 5.5 个百分点** |

**怎么读**：12.9% 是用"一个面积换算 + 两个查表"的纯几何办法做到的，**没用任何深度学习、没用深度图、没用侧视图**。它和 E2（7.9%）之间的差（≈5pp）是"几何估计粗糙"的代价；它和 18.4% 之间的差，是"硬币提供的真实尺度"的价值。

### 4.4 这一节说明了什么、没说明什么（重要，别过度解读）

- **没有**宣称打败了 Nutrition5K 主系统：ECUSTFD 是刚体食物域，Nutrition5K 以制备食物为主，两边病种不同。
- **证明了**：天花板的双因子分解（尺度歧义 + 密度离散）是**完整且可操作的**——在密度可观测处（刚体），只消掉尺度歧义（一枚 25mm 硬币、零学习）就足以突破单目天花板；在密度不可观测处（制备/堆叠），测试过的任何几何信号都不够。
- **落地含义**：一条工程决策规则——App 引导用户拍照时放参照物（硬币/卡片/标准餐具），刚体食物走几何估计路线，制备食物仍需交互或饮食先验。

## 5. 全局论证链：两组实验如何拼起来

把 §6.2–6.4 连起来看，是一条完整的"分解 → 证伪 → 验证"链：

```
Nutrition5K 单目天花板 18.4%（R²=0.39，61% 方差不可恢复）
        │
        ├─ MetaFood3D Phase 1（误差分解）
        │     └─ 分解出两个不可约因子：尺度歧义 + 密度离散(21.8%)
        │        且密度是主导（体积 ±10% 只贡献 2.6pp）→ 瓶颈是语义不是几何
        │
        ├─ MetaFood3D Phase 2'（证伪补救路线 A：学密度）
        │     └─ CNN 30.3% < 全局 42.3%，但输查表 26.2%
        │        → 外观只携带类别级密度信息 → 学习路线闭合
        │
        ├─ MetaFood3D Oracle-6（证伪补救路线 B：单图 3D 基础模型）
        │     └─ SAM 3D 绝对尺度失效（MAPE 100%），最好情况 ≈40% 重量误差
        │        → 天花板对 2025 最强模型同样成立 → 是信息问题不是容量问题
        │
        └─ ECUSTFD（建设性验证：补上缺失信息会怎样）
              └─ 硬币消掉尺度歧义 + 刚体域密度可观测
                 → 端到端 12.9% < 18.4% → 天花板可破，但靠的是加信息不是加模型
```

一句话：**这两组外部数据集实验把"18.4% 天花板"从一个经验数字，变成了一套被分解、被双向验证、且带工程处方的理论。**
