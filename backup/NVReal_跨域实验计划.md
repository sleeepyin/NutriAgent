## 一、动机与定位

**为什么做这个实验（三个理由，按重要性排序）：**

1. **审稿人必问的问题**："你的模型和共形区间在 Nutrition5K 之外的野外观测（in-the-wild）上表现如何？"——Limitations #5 目前只有一句"跨数据集泛化能力尚待验证"，用数据替换这句话。
2. **共形预测的可交换性假设检验**（最有学术价值的一点）：共形覆盖保证依赖校准/测试数据可交换。域偏移下 90% 覆盖率是否崩溃、崩多少——这是共形方法论文的教科书级补充实验，而我们恰好有部署好的校准器可以直接测。
3. **给 18.4% 天花板一个域外注脚**：我们的天花板论证全部基于 Nutrition5K（固定相机、餐厅场景）。NV-Real 是 iPhone 随手拍——如果域外退化巨大，说明天花板数字本身是域相关的；如果退化温和，说明管线稳健性尚可。

**不做什么（边界）：**
- 不做任何 NV-Real 上的训练/微调/校准——**严格 zero-shot，NV-Real 仅作测试集**
- 不追求刷分——这是诚实度量实验，不是竞赛
- 不与 NV-Real 原论文的 baseline 直接对比（协议不同），只引用作参考

## 二、数据集事实卡（已核实，arXiv 2401.08598）

| 项 | 值 | 对我们的意义 |
|----|----|----|
| 规模 | 889 图 / 251 菜 / 45 食物类型 | 小，够做测试不够做训练——正好是纯测试集 |
| 采集 | 真实生活手动拍摄（iPhone，任意角度/距离/光照） | 与 Nutrition5K 固定深度相机形成最大域差 |
| **深度** | **无（纯 2D RGB 数据集）** | ⚠️ 关键约束：我们的 4 通道 RGB-D 模型需模态适配（见第四节） |
| 标注 | **每食材实测重量**（逐食材称重） | 可做食材级 + 菜品级双重评测 |
| 营养 | 由食材重量 + 加拿大营养文件/包装计算 | 可测全营养管线（四营养素） |
| 分割 | 人工标注 mask | 直接复刻我们的"逐裁剪单食物"输入形态 |
| 获取 | Kaggle `nutritionverse/nutritionverse-real` 免费 | 下载无障碍（有 metafood3d 的 Kaggle 经验） |
| 视角 | 每菜多图（889/251 ≈ 3.5 图/菜） | 附赠：多视角预测一致性分析 |

## 三、三个研究问题

| RQ | 问题 | 度量 | 预期 |
|----|------|------|------|
| **RQ1 点估计域外退化** | 生产管线在野外观测上重量误差退多少？ | 菜品级重量 MAE/PMAE（vs 域内 652 hold-out 22.0%） | 退化 15-40pp（域差大） |
| **RQ2 共形覆盖域外存续** | Nutrition5K 上校准的 90% 区间在 NV-Real 上还剩多少覆盖？ | 部署校准器（冻结）→ NV-Real 覆盖率 + 宽度膨胀 | 覆盖率跌破 90%（可交换性破坏），量化跌幅 |
| **RQ3 类别结构迁移** | 退化是否遵循我们的刚体/制备二分（蓝莓悖论叙事）？ | 45 类手工标注刚体/制备 → 分组 PMAE | 刚体类退化 < 制备类（若成立，叙事闭环再+1） |

## 四、模态适配设计（关键技术决策）

我们的 v2 重量模型输入 4ch（RGB + depth），NV-Real 无深度。**三层方案，一次 GPU 训练解决：**

| 方案 | 做法 | 用途 | 成本 |
|------|------|------|------|
| **A. 深度置零** | 4ch 模型直接喂 (RGB, depth=0) | 测"喂错模态"的鲁棒性下界 | 0（纯推理） |
| **B. RGB-only 重训（主方案）** | 在 Nutrition5K 上重训 3ch 版 v2（同超参） | 干净的模态基线，域差测量的基准 | GPU 10-15 分钟 |
| C. 单目深度合成（备选） | Depth-Anything/MiDaS 合成相对深度 | 仅当 A/B 都失真才考虑 | +0.5 天，默认不做 |

**域差 vs 模态差的分解公式**（方案 B 的价值所在）：

```
模态差 = PMAE(N5K, 3ch重训) − PMAE(N5K, 4ch=22.0%)      ← 深度通道值多少钱
域差   = PMAE(NVReal, 3ch zero-shot) − PMAE(N5K, 3ch重训) ← 换数据集的纯域代价
总退化 = PMAE(NVReal, 3ch) − PMAE(N5K, 4ch) = 模态差 + 域差
```

方案 A 作为附加参考行（"不重训直接用的最坏情形"），论文主表用方案 B。

## 五、实验流程

### Phase 0：数据工程（0.5h，沙箱可跑）
- Kaggle 下载 → 解压 → 结构核验（889 图 / mask / 食材重量 CSV）
- 45 类手工标注 rigid/prepared（一次性，写进 label 映射表）
- 预处理：mask → bbox 扩 10% → RGB 裁剪 resize 224（复用 `test_100_samples_final.py` 的变换）
- 产出：`nvreal_crops.npz`（食材级裁剪 + GT 重量 + 菜品分组索引）

**Gate 0**：≥90% 食材能成功裁剪配对 GT；否则检查标注格式差异

### Phase 1：模态消融（Nutrition5K 域内，GPU 15min + CPU 10min）
- 3ch 重训 v2（RN18 + EffNet 双骨干，同超参种子）
- 域内评测：652 hold-out 上 4ch / 3ch / 4ch-深度置零 三行 PMAE
- **Gate M**：若 3ch 域内退化 >10pp（深度通道极重要），域差解读需带上模态警示；正常预期 2-6pp

### Phase 2：零样本跨域点估计（CPU 推理，1h）
- 3ch 模型 → NV-Real 全部 889 图食材裁剪
- 指标：食材级 MAE/PMAE、菜品级（Σ 预测重量 vs Σ GT）MAE/PMAE
- 分组：rigid vs prepared（RQ3）、逐类 top-K、多视角每菜品预测方差
- **Gate D**：域差分级——<10pp 温和 / 10-30pp 中等 / >30pp 剧烈，对应三种论文表述

### Phase 3：共形覆盖域外检验（CPU 10min，复用 Phase 2 预测）
- **部署校准器冻结**（`models/nutrient_conformal_calibrator.pkl` + AEC-S2m 重量侧），输入 NV-Real 预测
- 度量：重量区间覆盖率、宽度膨胀比；营养素区间（若 Phase 4 完成）四项覆盖率
- 这是 RQ2 的核心产出：**可交换性破坏的定量刻画**

### Phase 4：营养管线跨域（CPU 10min，可选但推荐）
- 菜品营养 = Σ(预测重量_i × 预测营养密度_i)（v4 密度模型 3ch 版？——密度模型也是 4ch，需同样置零或重训；**降级方案**：密度用 4ch-置零，报告时注明）
- vs NV-Real GT 营养 → Cal/Fat/Carb/Prot 四项 PMAE，对照域内 22.8/36.5/39.4/33.7

### Phase 5：论文整合（1h）
- **新增 5.8 Cross-Domain Generalization**（半页：协议 + 一张小表 + RQ1/RQ3 结论）
- **6.5 Limitations #5 重写**："单数据集评估"→ 实测数字 + 共形覆盖域外表现
- **共形覆盖结果**写进 5.6/5.7 附近作 honest limitation（预期覆盖不足 90%，如实报告）
- 附录 C 增补：`nvreal_crossdomain_experiment.py` + 数据获取说明

## 六、诚实协议（铁律）

1. NV-Real **零训练零校准零调参**——任何形式的使用其数据做超参选择都是新的泄漏事故（我们有 double-dipping 前科记录，绝不重犯）
2. 校准器/模型/阈值全部冻结，只用 Nutrition5K 产物
3. 3ch 重训只在 Nutrition5K 训练划分上做，评测协议与 v2 完全一致
4. 坏结果照登：覆盖崩溃、PMAE 爆炸都是合法且有价值的结果（写入失败/诚实记录，与项目惯例一致）

## 七、预期结果与三种解读（预注册）

| 情形 | 表现 | 论文表述 |
|------|------|---------|
| 乐观 | 域差 <10pp，覆盖 ≥85% | "管线在野外观测下稳健，共形区间部分存续" |
| **基准（最可能）** | 域差 10-30pp，覆盖 75-88% | "域偏移导致 X pp 退化、覆盖率跌至 Y%——可交换性假设在真实部署中需域内重校准"（诚实、有信息量） |
| 悲观 | 域差 >30pp 或覆盖 <70% | "固定相机训练的模型不可直接迁移；域自适应/重校准是部署前置条件"（强化 hybrid 拍摄协议的必要性论证） |

三种情形都能写——这正是本实验设计的安全边际。
